# 系统模板的产品开发流程

标准模板提供开发范式，不是要求原样安装的成品业务。一个 agent 负责一个系统或 UI 模块的实现，通过明确的接口协作；独立负责不等于无依赖，也不代表必须新增 RuntimeSystem 类。本流程不自动调度 agent。

必须读取 [开发规范](../development-rules/SKILL.md) 和对应系统 SKILL。框架规则必须遵守；示例产品的美术、数据、系统名称、存储键、流程去向和网络方案可以按产品需求替换。参考资料中的“当前”“必须”“保留”等历史约定，除共享编码规范外，只约束其所描述的参考实现，不自动约束新产品。

## 默认保留模板设计

- 用户未明确提出设计变更时，以任务指定版本或本次读取并记录的标准模板作为默认设计，保留布局、视觉、功能入口、交互和动画，不自行简化、重排、替换美术或重新设计。“参考范式”不是自由改版授权。
- 已明确的产品需求决定变更范围；只调整需求涉及的部分，保留其他设计。用户已经确认的设计选择不重复询问。
- 必要技术适配可直接进行，例如目标工程路径、符合规范的代码组织、数据绑定和已明确接口的接入，但不得改变可见表现与交互语义。技术限制导致无法保持一致时说明影响，不静默降级。
- 产品需求与模板存在尚未解决的冲突时，说明具体冲突并确认设计选择；继续完成不依赖该选择的工作。没有冲突且未要求改版时直接沿用模板，不为确认“是否沿用”阻塞开发。
- 未提供业务信息时，保留模板能力和明确标识的示例状态，不将示例数据用于正式业务、不虚构服务接口、不把占位交互描述为已经接入。涉及登录成功、保存、网络请求或系统切换等真实副作用时仍需明确产品契约。
- 此规则针对本次选用的标准模板，不要求恢复历史参考资料中的旧版本设计，也不自动覆盖目标产品已经确认的设计。

## 接收任务与定位

开始时从任务、目标工程和已连接项目中确定并记录：

- 目标产品、Unity 工程、当前系统和本次功能范围。
- 数据库模板 ID、读取到的版本、布局/动画/源码包状态。
- 产品页面与操作流程、数据来源、入口和退出行为。
- 已有框架版本、系统、公共类型及应复用的配置/资源。
- 允许修改的系统目录、资源目录与必要集成位置。

Studio 项目任务必须先按 AGENTS.md 核实显式 projectId 的 Unity 绑定及工程身份；不能拿 development 代替目标项目。独立指定工程的任务直接使用其明确路径。development 是参考工程，practice 是可选实践工程，都不是默认写入目标。

优先检查可用资料补齐信息。无法推断且会改变产品行为的事项集中询问，同时推进不依赖答案的结构工作；不要用范例数据或假服务填补未知产品需求。用户已给出的决定不重复询问。

## 读取标准并适配产品

1. 通过现有 GameCLI 模板工具读取标准模板和源码包，记录实际版本；标准动画读取其独立定义。SKILL 中历史版本号不是版本锁。
2. 将材料分成框架约束、可复用实现模式、产品特有示例。只读取任务需要的参考资料，不要求 agent 访问原 SV 工程才能开发。
3. 对照目标已存在代码设计本系统的 System/Entity/UI/VM；Loading、Launch 的组件边界分别遵守其 SKILL。数据由 Entity 管理，VM 负责展示绑定，业务协调不塞进 UI。
4. 按产品 UI 生成/调整预制体和序列化绑定，布局、Metadata、动画均使用正式 UnityCLI 工具链。不同产品不能盲用参考节点数量、GUID 或 Binding 顺序。
5. 按产品接口实现数据和交互。源码包是参考源码，不是完整依赖包；先识别类型、配置 ID、生成器、程序集和资源依赖，再复用或改写。
6. 固定文案使用产品的 propCommonText，按现有分配规则确定 ID，不直接复制参考数字；保存键按目标系统/实体的反射接口生成。

## 跨系统接口与所有权

- 每个 agent 优先写本系统目录与资源目录；不要为让本系统运行顺手开发其他系统。
- 明确输入数据、输出事件、谁发起打开/关闭、谁拥有持久化、异步回调代表哪一步完成。复用目标已有契约，不能各自复制同名公共事件或 RuntimeSystem。
- 公共事件、基础类、GamePlugin 注册、共享配置表和框架包是共享修改点。任务明确单 agent 负责集成时可按范围修改；多 agent 协作时由主 agent 或指定负责人统筹，系统 agent 提供所需变更，不各自覆盖整份共享文件。
- 无依赖实现时仍可完成本系统局部逻辑，并明确待接接口；不要伪造登录成功、生成空壳 Home 或绕过公共调度器。是否采用本地事件/示例数据由产品任务决定。
- 任务只有当前系统时，依赖方只读取。修改已有公共契约前列明受影响调用方；未明确的产品契约先澄清，不静默改变其他系统行为。

## 开发结果说明

保留简洁的开发记录：模板来源和版本、产品适配决定、修改路径、对外接口、必要共享集成项、尚未接入的产品接口。区分参考实现与本次实现，不依赖聊天历史解释代码。

产品开发不自动修改标准模板。只有用户明确要求将通用改进回流时，才同步源码/布局/动画并沿用草稿候选发布流程；不把产品专属需求反向覆盖标准。Git 提交推送和项目实例升级也按当次明确范围执行。

开发完成后按 [独立系统验收](../system-acceptance/SKILL.md) 的输入要求交付需求/设计版本、工程身份、修改范围、源码与资源版本、接口、复现步骤、自测及已知缺口。由另一名 agent 独立验收；开发 agent 的自测不能代替验收结论。验收问题返回本系统开发 agent 修复，再提交新版本复验。此流程不自动派发 agent。
