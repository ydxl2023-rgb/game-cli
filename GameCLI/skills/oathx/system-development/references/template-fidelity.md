# 系统模板提取、制作与复验

从原作提取标准模板时，用原作和用户确认的取舍建立基准。使用模板开发产品时，用指定模板版本和产品已确认的变更建立基准。后续 agent 应能仅凭交付资料复现范围内的行为。

## 提取时记录什么

在本系统的开发资料中，按有独立行为或表现的场景记录下列内容。相同布局和行为可共用一条用例，列出覆盖的入口。纯逻辑系统用事件和状态迁移描述场景。

| 场景与入口 | 来源与版本 | 输入、配置与资源依赖 | 操作与预期结果 | 已确认的差异或待核实项 |
| --- | --- | --- | --- | --- |
| 填写页面、组件状态或事件 | 指向原作截图、运行记录、源配置或已发布模板 | 写出能复现的配置键、示例值或事件参数 | 写出可观察的画面、时序、数据变化或副作用次数 | 标出证据缺口及影响范围 |

静态预制只能说明初始结构。沿正常入口追踪运行时创建的子项、数据绑定、配置选择、动画触发和生命周期事件。将动态依赖随模板交付，注明哪些由产品提供。参考画面与源数据对应不上时，保留两者的版本与条件，把推测单列为待核实项。

## 制作时怎样暴露问题

- 为每种不同的表现或行为准备足以触发它的最小 Demo 数据，走实际加载、绑定或事件路径。根据系统选择能改变结果的边界，例如跨行、长文本、空数据、状态切换或重复通知。把用例引用的条目纳入交付的配置或示例资料，记录复位方法。
- 有 UI 时，明确尺寸由哪个预制或布局组件控制。列表的步长要覆盖实际可见边界和间距，文字与图标保持设计比例；选用换行、滚动或自适应哪一种，以参考交互为准。在目标画幅检查首尾元素、遮挡和裁切。
- 有动画时，从实际入口触发，核对触发时机、播放过程、终态和交互恢复；单张终态截图不能回答动画是否播放。纯逻辑系统则重放输入，核对状态、事件顺序和副作用。
- 修复已复现的问题时，在本系统验收资料中留下最小触发条件和可观察的通过标准。只有跨系统都成立的原则才写回共享规范。

## 独立复验与交付

开发 agent 在本系统开发资料留下基准、Demo 数据、入口与复现步骤。验收 agent 按本系统 acceptance SKILL 选用具体用例，自行准备初始状态并从正常入口重放。逐项对照同一版本、数据和条件下的预期结果。视觉用例记下分辨率和关键帧，逻辑用例记录输入、事件及最终状态。适用的 verify prefab、verify code 结果与运行证据分别记录。

每项结果标明通过、失败或未验证，记录证据位置和已批准差异。验收范围仅覆盖实际运行的场景。涉及标准模板入库或发布验证时，从待验的数据库模板版本在干净测试工程中恢复所需代码、资源、动画和配置，复跑代表用例；记录版本、工程和结果。仅验证 development 工程时，数据库版本的可重建性列为未验证。

## 使用 CLI 重放系统用例

在本系统 acceptance 目录维护场景文件。运行 `gamecli verify integration --project <项目ID> --template <模板ID> --scenarios <用例.json>`。命令通过绑定工程的 UnityCLI 新建一次 Play 会话；已有 Play 会话时，报告记为未验证。每条调用或测量的实测值、截图及工程指纹保存在报告的 evidenceDirectory。用例通过后仍按本系统的其余验收条件逐项审核。

用例格式为 `gamecli-scenarios/1`，包含 templateId 和按顺序执行的 steps。每步使用唯一 id。直接参考[商店用例](../../system/shop/acceptance/scenarios.json)和[纯逻辑流程用例](../../system/master/acceptance/scenarios.json)。两份示例调用 development 工程的 Editor 探针；移植到产品时替换为该产品的已绑定入口、可观察结果和 Demo 数据。验收应选用可复位的测试账号或本地存档。

- `call` 指定 type、member、可选 args 和预期返回摘要 equals。会改变业务状态的操作只调用一次。
- `wait` 用相同字段轮询只读方法，支持 timeoutMs 和 stableMs。记录观察窗口，避免将有限时间内的结果扩大为长期保证。
- `layout` 指定唯一活动容器路径 path、可选直接子项名 name、子项内的相对路径 target 和预期 count。按场景选用 columns、separate、fullyVisible、uniformScale 或 inside。inside 引用之前的测量步骤，通过同一实例 ID 比较父子区域。
- `screenshot` 将当前 Game 画面保存到本次证据目录，供独立验收 agent 对照字体、遮挡、动画或美术。前面布局断言失败时仍可留存画面。

UnityCLI 也可单独执行 `measure --path <容器路径> --name <直接子项名> --child-name <子项内目标路径>`。输出采用屏幕像素坐标，原点在左下。visibleCount 统计与屏幕和启用的父级遮罩矩形相交的活动目标；数值反映矩形边界。透明度、异形蒙版、旋转后的精确轮廓及其他控件遮挡需要结合截图判定。支持的断言与参考分辨率由各系统用例选择。
