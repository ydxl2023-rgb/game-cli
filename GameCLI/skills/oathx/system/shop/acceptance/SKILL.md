# Shop 验收

独立复验时按[模板提取与复验](../../../system-development/references/template-fidelity.md)对照来源、示例输入和运行证据，具体判定采用本系统用例。

由开发者以外的 agent 执行，先读[开发契约](../development/SKILL.md)和[共享编码规范](../../../development-rules/SKILL.md)。只审查交付并记录缺陷，不代替开发者修改。核实目标工程身份、模板版本及交付范围，拒绝把旧道具商店当作大厅商城。

核对主预制、内嵌分页、独立 Widget 及其专属资源均位于 `Assets/Data/Widgets/Shop/`，并逐页对照 Widget 加载路径和模板材料清单。跨系统复用的商品卡按 Micros 规则检查。

## 专项检查

1. 主商城、充值子页、礼包子页、礼包购买弹窗均存在；核对 VM 与 Metadata 的实际字段及组件，不以字段数量相等代替目标正确。
2. 分类和二级页签标题、选中态、点击索引正确；充值与礼包数据切换、滚动和 Cell 复用不串数据、不叠加监听。关闭的模板 Cell 不应额外显示。
3. 名称、图标、价格、实际奖励、限购状态正确；占位文本不能泄露到可见界面。明确示例数据、本地模拟与尚未接入的运营分支。
4. 取消不改变余额/奖励/限购；确认成功只处理一次；连续点击、余额不足、售罄、无选择、分类切换后的旧确认均验证。重新打开保留约定的本地状态，不能悄悄补满余额。
5. 主界面、页签、货币/返回栏、商品、礼包弹窗的入场，以及所交付点击反馈实际播放。检查首次与再次打开、Cell 复用、动画终态及交互门禁恢复。静态 Controller 引用和手动 SampleAnimation 不足以证明自动播放。
6. 系统停用关闭所有拥有的页面并清理待确认状态；异步加载期间退出应专门验证。未验证必须写明，不把仅正常关闭的结果推广到该情形。
7. 固定文案由 propCommonText 解析；验证末行、格式参数、导表输出与运行时加载。独立 configurations 源表哈希、合并条目和源码引用一致。
8. 数据库主模板及伴随页面的源码、预制、图片、原生动画、网页动画与当前实现一致。分别运行适用的 verify code / verify prefab，并解释未覆盖诊断。

## 结果

保存原始 CLI 证据和复现步骤；区分静态检查、运行自测、独立运行验收。逐项列出通过、失败、未验证及明确未交付的扩展分支。首版没有真实支付，不测试或宣称真实订单与到账成功。

## 实体边界验收

按开发规范的统一实体职责，检查本系统业务数据与规则归属、输入与输出集合隔离、非法操作不改变状态，以及 System/UI 无直接改写内部数据。纯展示模块不强制新增实体；区分实体数据与展示/调度状态。


## 商品卡组合验收

检查两种商品卡为独立 prefab，页面中保留嵌套源引用，内部引用共享 ItemSlot。核对 Fancy.cellPrefab、ProductTemplate 与全部 Metadata；验证字符串路径实际加载、礼包数量、价格/限购/售罄及顶层点击命中。独立实例重复绑定同一个 VM 后数据仍保留，解绑后旧 VM 不更新控件。对比拆分前外观及原动画，不能以槽位默认底板覆盖充值大图。源码与 materials、bindings、配置依赖版本必须一并同步；普通路径加载通过不代表快速换图、加载失败或异步关闭已验收。

## 可执行用例

使用本目录的[特惠商品用例](scenarios.json)验证从登录、大厅进入商城后的 12 张商品卡。断言两行六列、卡片等比、互不覆盖、价格栏完整位于对应卡片内，并保存截图。其余分页和交互另按专项检查验证。
