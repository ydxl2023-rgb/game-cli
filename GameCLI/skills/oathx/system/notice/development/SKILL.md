# Notice 产品开发

开发交付后由另一名 agent 按 [Notice 独立验收](../acceptance/SKILL.md) 和产品需求验收，覆盖内容展示、超链接、关闭/重开及指定的标准弹窗动画。

必须读取 [系统开发流程](../../../system-development/SKILL.md)、[开发规范](../../../development-rules/SKILL.md)、[Core](../../../core/SKILL.md)、[Widget](../../../widget/SKILL.md)、[Widget Extension](../../../widget-extension/SKILL.md)。数据实体需要时读取 [Entity](../../../entity/SKILL.md)。

## 默认设计

未明确提出设计变更时，保留选用标准模板的布局、视觉、交互和动画，不自行改版。仅做保持表现与行为一致的必要技术适配；产品契约缺失时不虚构业务。遵循[共享默认规则](../../../system-development/SKILL.md#默认保留模板设计)。

## 范式与边界

- 模板 ID：SvNotice。读取实际发布的布局、动画和源码包，不把原 SV LoginNoticeView 当作 Oathx 的必需依赖。
- NoticeSystem 负责公告业务和数据接入；UINotice/VMNotice 负责内容呈现与交互绑定。通过产品系统协调入口提出关闭请求，不让 Login 管理公告内部业务。
- 单条默认公告、暂无公告、一周免打扰以及无通信是 GameCLI 示例的产品选择。未来产品是否联网、多公告、缓存或免打扰由需求决定。
- 标准弹窗动画来源为独立标准动画库 dialog.open.scale，读取明确版本并映射到产品内容容器；全屏遮罩不参与缩放。Unity 动画和预演动画是两种消费格式，不以仅有 .anim 代替模板动画数据。

## agent 开始时确定

公告数据接口、条目结构、标题/正文/图片/链接格式、空态与错误态、打开/关闭入口、缓存及免打扰策略。缺少正文时不编造正式公告；测试文本必须明确标识且得到任务范围支持。

## 实现路径

1. 获取产品公告 UI 与模板最新源码，按本次页面设计明确列表、正文和交互区域。
2. 按共享目录规则组织 Notice/UI、Notice/VM；其他代码放 Notice 根目录。历史参考的 Components 子目录只用于已有示例维护，不自动复制为新产品规范。
3. 按实际 VM 生成 Metadata 与序列化引用，处理正文布局、滚动裁剪和背景拦截，不依赖历史绑定数量。
4. 需要超链接时复用并适配参考文本组件，明确允许的协议和点击行为，避免滚动拖动误触；内容格式由产品契约定义。
5. 将产品数据转成展示模型，固定界面文案走 propCommonText；公告正文作为动态内容。按产品契约发出系统关闭请求并处理 OnDetive。
6. 将标准打开动画应用到窗口主体，保留遮罩、正文和关闭按钮的正确层级；不把参考固定节点路径当成产品通用路径。

开发结果说明数据入口、内容格式、对外事件和动画来源。源码清单、SV 提取证据、历史资源路径等按需读取 [参考实现](references/gamecli-example.md)。未来产品开发无需先提取 SV，也不自动覆盖标准数据库模板。
