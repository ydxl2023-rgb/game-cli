# Actor 开发

先读并遵循 [共享编码规范](../../../development-rules/SKILL.md)、[Entity](../../../entity/SKILL.md)、[Core](../../../core/SKILL.md) 和 [系统开发流程](../../../system-development/SKILL.md)。涉及资源加载时读 [Bundle](../../../bundle/SKILL.md)，实际使用 Avatar 组件时再读 [Avatar](../../../avatar/SKILL.md)。完成后交由另一名 agent 按 [Actor 验收](../acceptance/SKILL.md) 检查。

本 Skill 定义角色开发职责，不自动创建 agent、安装系统或授权提交、推送、发布模板。Actor 可以是宿主系统内的角色模块，不因目录名称强制新增 ActorSystem。

## 开始前确认

从目标工程和已确认需求确定角色类型、实例 ID 与配置 ID、数据所有者、创建与回收入口、已有状态、资源格式及更新时钟。明确本轮是角色基础结构、行为扩展还是资源接入；只实现获授权范围。

读取目标版本 `XEntity`、`XEntityManager`、`XActionStateMachine` 与宿主调用方，核对真实 API 和更新方式。若任务指定数据库模板，读取其实际版本及配置包；没有模板不虚构模板 ID。提取或制作模板时依照 [模板提取与复验](../../../system-development/references/template-fidelity.md) 建立对应角色场景基准。

需要参考已落地结构时，按需读 [miniwow 实现参考](references/miniwow.md)。参考中的路线、状态和 Spine 是产品选择，不是所有角色的固定规格。

## 职责与依赖方向

| 部分 | 所有权与接口 |
| --- | --- |
| ActorEntity : XEntity | 单个角色的身份、逻辑位置、方向及已授权的属性、行动状态和规则。通过操作方法校验并改变数据，不持有 Shape、GameObject、Transform、Animator 或 Spine 对象。Unity 数学值类型可使用。 |
| ActorShape : XActionStateMachine | 每个角色独立的表现状态机，读取实体并更新位置、朝向、动画与表现效果。绑定不初始化或重置实体，解绑、隐藏和销毁显示不改变实体业务数据。 |
| 宿主集合实体 | 按实例 ID 管理多个 ActorEntity，负责集合约束与实际实体创建、查找、释放；实例 ID 与配置 ID 分开，不暴露可直接修改的内部集合。 |
| 宿主 System / 场景绑定组件 | System 编排配置、资源、绑定及退出；场景组件持有序列化引用、复制初始化值并转交交互意图，不重复实现实体规则。 |

一个实体代表一个实际角色，集合实体代表角色集合。先检查 XEntityManager 的键规则；若按类型唯一注册，就注册集合实体，不能把多个同类型角色当作管理器中的多个唯一槽位。

角色行为更新必须有明确且唯一的逻辑时钟，独立于 Shape 是否启用。系统或集合负责推进实体，Shape 驱动表现时钟。明确暂停、离场和销毁的业务语义；不能用隐藏显示来暗中暂停逻辑。物理或导航接入需要输入/结果适配层，并由实体确认结果，不能恢复 Shape 对权威位置的无约束回写。

## 状态机与扩展

- ActorShape 必须继承 XActionStateMachine，每实例注册和保存自己的状态。使用框架注册、进入、更新、离开和清理能力，不能只改继承名而保留另一套平行状态机。
- 业务行动阶段属于实体，表现状态属于 Shape。先定义两者映射和切换所有权；动画播放完成不能自行认定伤害、奖励、建筑消费等业务已结算。
- 注册在首次使用前完成，重复绑定不重复注册；每帧只更新一次表现机器。同一状态持续刷新不得重复进入或重启动画，除非明确收到重新播放指令。
- 动画播放放在状态进入回调，持续表现放在更新回调，临时监听、效果和资源在离开或解绑时释放。采用清晰的注册扩展点；具体用继承还是组合按现有项目结构选择，不预建空战斗状态。
- 核对当前框架对枚举比较、SetState、清理和栈操作的语义。不能仅凭方法名假设同状态 SetState 会自动去重；用值比较判定转换。若需要现有实现不支持的能力，说明具体缺口并局部处理，不顺手重构框架。
- 允许短暂表现状态时，规定优先级、完成或中断条件、如何回到实体状态，避免下一帧无条件映射覆盖受击等表现。

## 资源、配置与初始化

动画名称按共享规范，在使用类之前的常量类型集中声明 `const string`；字段默认值、动画查找、播放及编辑器制作代码复用常量。序列化映射可保留，空的可选动画与缺失的必需动画分别处理，不静默伪造资源成功。

属性、移动参数、模型和资源选择按产品配置契约接入；配置表按 [配置包规范](../../../system-development/references/configurations.md) 导出加载。场景查找和加载通过场景表及生成别名取得路径，不使用业务路径常量替代查表。固定作者路点可以作为场景输入，导入实体时复制为值，实体不保留 Transform 引用。

使用原生 Unity API / UnityCLI 创建或更新预制、场景和序列化绑定，迁移保留 GUID；不手写 YAML。按实际渲染方案检查资源版本、依赖、动画名、朝向与缩放；Spine 不作为所有产品的强制依赖。

初始化先校验再提交。复制可变输入，非法 ID、重复实例、无效数值或必需资源缺失不能留下部分实体或绑定。异步创建完成前先检查宿主是否仍有效，迟到结果不得重建已退出角色。

解绑清空表现状态及引用，但实体由所有者明确释放；重新绑定按当前实体状态恢复。销毁实体后旧 Shape 引用不得继续表现为活跃角色。对象池复用时清理上次状态和回调，不把前一实例 ID 或数据带入下一角色。

## 交付

交付角色职责、状态映射、实例所有权、更新和暂停策略、配置/资源来源、扩展接口、复现步骤与当前限制。执行目标工程编译、适用的 GameCLI 代码检查及本次改动相关行为验证；代码检查不能代替运行验收。

按 Actor 验收提供冻结的源码/资源版本和证据。角色模块通过不表示完整战斗、寻路、存档或建筑业务已经完成。
