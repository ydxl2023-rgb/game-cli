# RedDot 验收

先读 [开发契约](../development/SKILL.md) 和 [开发规范](../../../development-rules/SKILL.md)。只读检查，由开发者修复发现的问题，不以编译通过替代运行验证。

- 验证工程绑定、配置源表与导出资源一致、启动注册生效；未知条件、缺失父节点、循环和非法标识必须明确拒绝。
- 零值默认隐藏；发送正数后显示，发送零后隐藏，父级数量随子项更新；无变化不重复发送 RedDotChanged。负数和未知 ID 不改变状态。
- 不发送业务事件、只修改测试条件输入，再打开/关闭 Widget，验证触发重新检测；对应配置开关应有效。
- 同帧重复事件合并；关闭页面后状态保留，重开立即恢复；重复开关不增加监听；服务停用隐藏并取消任务，服务重开能够接管已打开页面。
- 静态验证所有序列化 ID 有配置、对象引用有效；Count 模式要求 Text；隐藏目标不应解除 Scope。
- Home 的红点控制从原数组及实体枚举迁出，NEW、广告、掉落和活动显隐仍可工作。检查完整截图和实际红点显隐。
- 纯逻辑服务不需独立窗口或 VM；验收配置、代码与宿主 Widget 集成。测试报告区分原始工具证据、独立复核和未覆盖范围，不伪称已接入邮件等业务。

## 实体边界验收

按开发规范的统一实体职责，检查本系统业务数据与规则归属、输入与输出集合隔离、非法操作不改变状态，以及 System/UI 无直接改写内部数据。纯展示模块不强制新增实体；区分实体数据与展示/调度状态。
