# Master 独立验收

由未参与本轮 Master 实现的 agent 执行。本技能只定义本模块验收，不自动派发 agent 或启动试跑。阅读[本模块开发契约](../development/SKILL.md)、[编码规范](../../../development-rules/SKILL.md)、[Core](../../../core/SKILL.md)及 [CLI 命令说明](../../../../../integrations/codex/cli/README.md)。

## 开始前

- 收集产品需求、已确认设计变更、模板版本、实际源码/资源路径、接口与测试数据，记录提交及开始/结束文件哈希。模板是范式；没有明确改版时保留所选设计，不用历史示例强加业务。
- Studio 项目核实显式 projectId 的 verified Unity 绑定及 ProjectSettings/GameCLIProject.json 两个 ID，只在匹配工程操作，不默认选 development/practice。
- 对同一 Editor 串行操作；验收不修改业务代码、资源、基准、标准模板或规则。缺陷交回本模块开发 agent；交付改变后重新冻结并复验受影响项。

## 调度交付契约

读取 MasterSystem 实际发布源码（纯代码模板，无 UI），明确系统清单、公共事件载荷、登录前后顺序、完成回调语义及实体/存档责任。SystemActive、SystemDetive、LoginSucceed 按产品实际契约采用；Home、Fight、默认玩家字段不是必选依赖。

## Master 专属检查

| 检查项 | 操作与证据 |
| --- | --- |
| 初始化 | 从真实插件/注册入口定位 Master 和实体初始化时机，核对 OnActive 订阅，避免测试手动调用 handler 绕过真实调度链。 |
| 激活与停用 | 发送约定事件，观察目标系统状态和回调次数；反复请求/重复类型按产品约定处理，不在事件枚举期间引发集合修改异常。 |
| 无效输入 | 对 null、不支持类型、抽象类型/自身类型等实际契约边界验证拒绝语义和有效状态保留，不以吞异常伪造完成。 |
| 登录门控 | 需求规定等待登录成功时，成功前不得启动后续流程；成功事件携带正确身份，重复/无效/失败结果不错误推进。仅任务明确本地试跑时接受本地发送，不能伪造网络认证。 |
| 实体职责 | 数据由实体持有；加载/保存/通知的时序与失败处理符合需求。没有存档需求不为验收增加保存代码、字段或 RPC。 |
| Master 自身退出 | 停用 Master 后再发事件，原订阅不应继续路由；重新激活后只处理一次。检查延迟调度在退出/重进时不会应用过期请求。 |
| 完成语义 | 系统激活步骤完成不代表其 UI 异步加载完成；使用状态/事件日志与计数分别证明，不将一个回调当成全部业务就绪。 |

Master 不运行 verify prefab，不生成 UIMaster/VMMaster/占位预制，其 UI、VM 绑定、截图、动画检查明确为 not-applicable。通过事件轨迹、实体前后值、目标系统状态与调用次数证明行为。需要测试替身时仅隔离在测试材料中，并说明未覆盖的真实跨系统集成。

## 自动检查与取证

在 integrations/codex 下用 pwsh.exe 执行，system 参数使用实际目录名：

```powershell
.\gamecli.cmd verify code --project <项目ID> --system Master
```

保存原始 JSON、退出码及代码 reviewRequired；注释率/空行率只作统计，不设臆造门槛。执行目标 Unity 编译和 Console 检查，不能把静态检查当作运行通过。共享基础类、公共事件及插件注册位于 Master 目录外时另外列明源码审查范围；目录扫描通过不证明这些集成点已检查。

运行证据记录事件输入、分发帧序、预期/实际状态、接收次数及实体前后值；仅方法返回成功不证明目标系统真的完成激活。临时探针不进入产品交付，结束清理测试实例/探针并记录 Play 状态；不保存测试修改到产品资源，不擅自调用真实服务或清除存档。

## 本模块报告与复验

交付单独的本模块报告：需求与用例映射、版本/哈希、源码和资源覆盖范围、原始 CLI 证据、运行证据、缺陷定位/复现/影响/负责人、未覆盖项及复验关联。证据放指定持久化目录，Library 临时路径不能当长期归档。

每项采用 passed / failed / incomplete / not-applicable。不满足明确需求是 failed；必要证据或契约不足是 incomplete；只有确实不适用的检查才能 not-applicable。存在缺陷则总体 failed，无缺陷但必需项有缺口则 incomplete；所有适用必需项充分证明才 passed。补证说明证明范围，保留 CLI 原始状态。修复交回本模块 development agent，复验修复及其依赖，不合并不同交付版本的通过项。

本模块通过不等于跨系统产品全流程通过。验收不授权 Git 提交推送、标准模板发布或上线。
